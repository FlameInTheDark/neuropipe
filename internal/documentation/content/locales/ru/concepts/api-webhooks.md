# API и вебхуки

HTTP API Neuropipe необязателен и по умолчанию выключен. Пока он не включён в
**Настройки → API и вебхуки**, приложение не открывает HTTP-слушатель, а
триггеры Local Webhook не могут принимать запросы.

На этой странице описаны настройка API и безопасная доставка подписанного
вебхука. Пины и поведение в графе см. в [справке узла Local
Webhook](docs:node:trigger:webhook).

## Что необходимо

Для работы вебхука API должен быть включён; в опубликованном пайплайне должен
быть настроен Local Webhook; опубликованной ревизии должно быть выдано доверие
для автономного запуска; отправитель должен подписывать точные сырые байты
тела секретом триггера. При отсутствии любого условия Neuropipe не запускает
пайплайн.

## Включение локального API

Откройте **Настройки → API и вебхуки**. По умолчанию API слушает
127.0.0.1:7878, а обычные маршруты /v1 требуют токен. Токен хранится только в
защищённом Windows-хранилище. Административный API включается отдельно и
требует режим токена.

Не-loopback адрес требует явного подтверждения. Встроенный сервер обслуживает
только HTTP. Для доступа по сети установите перед Neuropipe reverse proxy,
завершающий TLS, и ограничьте доступ к нему.

При выключении API слушатель останавливается. Узлы и привязки сохраняются, но
их webhook-маршруты недоступны.

## Настройка триггера

1. Добавьте в черновик **Local Webhook**.
2. Укажите уникальный **Path**, например /build-complete. Крайние косые черты
   нормализуются.
3. Создайте или выберите длинный случайный **Signing secret** в выборе
   секретов.
4. Соедините **Start** с первым узлом действия или потока, а для типизированного
   чтения данных запроса используйте **Get Field**.
5. Сохраните и опубликуйте пайплайн, затем включите и подтвердите доверие к
   привязке триггера.

Адрес доставки:

~~~text
POST http://<адрес>:<порт>/hooks/<путь>
~~~

При настройках по умолчанию и пути /build-complete это
http://127.0.0.1:7878/hooks/build-complete.

## Подпись сырого тела

Каждый запрос должен содержать:

~~~text
X-Neuropipe-Signature: sha256=<шестнадцатеричный HMAC-SHA-256 сырого тела>
~~~

Ключ HMAC — Signing secret. Подписываются ровно те байты, которые отправляются.
Форматирование JSON, смена переводов строк или кодировки делают подпись
недействительной. Webhook-маршруты используют этот HMAC вместо bearer-токена
API; маршруты /v1 остаются отдельными.

~~~powershell
$body = '{"event":"build.completed","build":42}'
$key = [Text.Encoding]::UTF8.GetBytes($env:NEUROPIPE_WEBHOOK_SECRET)
$bytes = [Text.Encoding]::UTF8.GetBytes($body)
$hmac = [Security.Cryptography.HMACSHA256]::new($key)
$hex = (($hmac.ComputeHash($bytes) | ForEach-Object { $_.ToString("x2") }) -join "")

Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:7878/hooks/build-complete" -ContentType "application/json" -Headers @{ "X-Neuropipe-Signature" = "sha256=$hex" } -Body $body
~~~

Корректная доставка получает **202 Accepted** и запись выполнения. Она ставится
в очередь; итог смотрите в журнале выполнения.

## Значения в Blueprint

Триггер выдаёт объект с trigger: webhook, сырым текстом body и необязательным
json для валидного JSON. В **Get Field** добавьте, например, json.event как
текст и json.build как число. Невалидный JSON всё равно допустим при корректной
подписи — тогда используйте body.

## Безопасность и поиск проблем

- Оставляйте 127.0.0.1, если удалённый доступ действительно не нужен.
- Используйте отдельные случайные секреты и пути для каждой системы-отправителя.
- Публикация изменённой ревизии может потребовать нового доверия.
- Ошибка соединения обычно означает выключенный API, неверный порт или адрес.
- 404 означает неизвестный или выключенный нормализованный путь.
- Неверная подпись означает различие секрета, заголовка или сырых байтов.
- 202 подтверждает только постановку в очередь; при отсутствии результата
  откройте возвращённое выполнение.

Полный контракт приведён в [справке узла Local Webhook](docs:node:trigger:webhook).
