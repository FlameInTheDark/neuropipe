# Удалённые исполнители

Удалённый исполнитель — это автономный запускатель пайплайнов Neuropipe, устанавливаемый на другой машине. Он содержит полный движок Blueprint, поэтому любой пайплайн, работающий локально, работает и там: HTTP, терминал, Git, файлы, JavaScript, ИИ-узлы, отчёты, чат, Twitch и другое. Neuropipe взаимодействует с ним по аутентифицированному gRPC-соединению.

## Что исполнитель размещает сам

Исполнитель автономен там, где это оправдано:

- **Расписания cron** срабатывают на машине исполнителя даже при закрытом Neuropipe. Расписание срабатывает автономно, только если его опубликованная версия была отмечена доверенной и включена на момент развёртывания; доверие передаётся вместе с развёртыванием и обновляется при изменениях.
- **Кнопки**, горячие клавиши, вебхуки, триггеры чата и события Twitch по-прежнему исходят из Neuropipe. Каждый запуск пайплайна, привязанного к удалённому исполнителю, передаётся ему по gRPC и отображается в локальной истории запусков.

Триггеры наблюдения за файлами развёртываются как метаданные, но пока остаются на стороне десктопа, как и остальные передаваемые триггеры.

## Где хранятся данные

Ваша машина сохраняет всё важное:

- Определения пайплайнов, версии, решения о доверии, история запусков, отчёты и беседы остаются в локальном рабочем пространстве.
- В режиме по умолчанию **Через Neuropipe** вызовы моделей пересылаются по защищённой сессии к настроенным провайдерам. API-ключи никогда не покидают эту машину.
- Учётные данные баз данных и OAuth Twitch остаются локальными; узлы SQL и Twitch на исполнителе обращаются обратно через сессию.

При переключении исполнителя в режим **На исполнителе** провайдеры настраиваются прямо на той машине. Ключи, введённые в диалоге настройки, сохраняются один раз в собственном хранилище исполнителя и не могут быть прочитаны обратно.

Глобальные переменные на стороне исполнителя изолированы для каждого исполнителя: они создаются пайплайнами неявно, сохраняются на исполнителе и никогда не синхронизируются с вашим рабочим пространством. Интерактивные диалоговые узлы на исполнителе завершаются явной ошибкой — отвечать некому.

## Установка исполнителя

1. Скачайте архив для целевой платформы со страницы релизов (`neuropipe-executor-*` для Windows, Linux и macOS).
2. Запустите демон один раз:

   ```bash
   neuropipe-executor serve
   ```

   Без конфигурации он создаст каталог `data`, сгенерирует надёжный общий токен, выведет его **ровно один раз**, сохранит в `data/token.txt` и начнёт слушать порт `:47777`. Скопируйте показанный токен в Neuropipe при регистрации исполнителя.
3. При необходимости положите рядом с бинарным файлом `executor.json` со статическими настройками:

   ```json
   {
     "listen": ":47777",
     "dataDir": "data",
     "tokenFile": "token.txt"
   }
   ```

   Флаги командной строки переопределяют файл на один запуск: `neuropipe-executor serve --listen :5000 --token <значение> --data-dir D:\executor`. Также работает переменная окружения `NEUROPIPE_EXECUTOR_TOKEN` — удобно для определений служб.
4. В Neuropipe добавьте исполнителя с его адресом (например, `192.168.1.50:47777`) и проверьте соединение.
5. В Linux зарегистрируйте его как службу systemd, чтобы расписания переживали перезагрузки.

Полезные команды:

- `neuropipe-executor status` — показывает эффективную конфигурацию, откуда возьмётся токен (никогда — само значение) и сколько пайплайнов и запусков сохранено локально.
- `neuropipe-executor token generate` — заменяет общий токен, сохраняет его и выводит новое значение ровно один раз; после этого обновите Neuropipe.
- `neuropipe-executor --version`.

Безопасность транспорта: аутентификация токеном обязательна всегда. Для трафика через недоверенные сети завершайте TLS перед исполнителем (`tlsCert`/`tlsKey` в загрузочном файле) или используйте VPN, затем включите опцию «Использовать TLS» в регистрации.

## Создание пайплайнов для исполнителя

Нажмите «Новый пайплайн» в списке пайплайнов и выберите исполнителя в поле «Запускается на». Пайплайны для удалённых исполнителей отображаются в категории «Удалённые» и несут значок своего исполнителя в редакторе. Публикация автоматически разворачивает опубликованную версию — вместе с используемыми пользовательскими функциями; если исполнитель недоступен, публикация всё равно сохраняется локально, а повторить развёртывание можно действием «Синхронизировать с исполнителем» или автоматической синхронизацией при восстановлении связи.
