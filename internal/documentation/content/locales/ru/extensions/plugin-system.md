# Система плагинов

Плагины Neuropipe — это локальные независимо версионируемые бандлы. В бандл
входят plugin.json, исполняемый sidecar, необязательные декларации узлов и
Markdown-документация. Пользователь выбирает корневой каталог в
**Настройки → Расширения**, затем явно запускает повторное обнаружение.
Десктопный renderer никогда не читает каталог плагина напрямую.

## Текущая граница v1

Сейчас Neuropipe поддерживает **обнаружение бандлов, диагностику и загрузку
документации**:

- рекурсивно ищет plugin.json;
- проверяет идентичность, версию API и указанный sidecar-файл;
- показывает имя, версию, описание, число объявленных узлов и состояние в
  настройках;
- безопасно загружает необязательные Markdown-страницы из здоровых бандлов.

Хост пока не запускает sidecar, не добавляет объявленные узлы в Библиотеку и
не выполняет действия плагина. Статус **Healthy** означает только успешное
обнаружение, а не запуск процесса или самопроверку.

Сегодня может работать бандл документации/обнаружения. Объявленные action,
trigger и tool-узлы не следует использовать до реализации Emerald-совместимого
рантайма ниже.

## Структура бандла

~~~text
<корень-плагинов>/
  acme-status/
    plugin.json
    sidecar.exe
    docs/
      status.md
~~~

Относительный путь к executable разрешается от каталога с plugin.json, поэтому
полный бандл можно переносить. Абсолютные пути текущий валидатор принимает, но
они не подходят для распространяемых бандлов.

## Манифест

| Поле | Обязательно | Назначение |
| --- | --- | --- |
| id | Да | Стабильный уникальный идентификатор плагина. |
| name | Да | Отображаемое имя в настройках. |
| apiVersion | Да | Должно быть ровно v1. |
| executable | Да | Существующий файл, не каталог. |

Версия и описание рекомендуются. Минимальный манифест:

~~~json
{
  "id": "acme-status",
  "name": "Acme Status",
  "version": "0.1.0",
  "description": "Локальные проверки статуса.",
  "apiVersion": "v1",
  "executable": "sidecar.exe",
  "nodes": [],
  "documentation": []
}
~~~

Args читаются, но executable пока не запускается. Не помещайте в манифест
секреты, токены, приватные URL или данные клиентов.

## Декларации узлов

pkg/pluginapi содержит Bundle и NodeSpec. В декларации есть id, kind, label,
описание, иконка, цвет, capabilities, выходы и поля конфигурации. Сейчас эти
записи только увеличивают показываемое число узлов. Они не создают узел в
Библиотеке и не валидируют конфигурацию. Тем не менее сохраняйте их id
стабильными.

Пакет также содержит Go-интерфейс Action с Validate и Execute. Это не
межпроцессный протокол: отдельно скомпилированная программа не становится
исполняемой только от объявления интерфейса, потому что в Neuropipe пока нет
RPC-клиента и жизненного цикла sidecar.

## Emerald-совместимый рантайм

Emerald использует Go-first sidecar на HashiCorp go-plugin с транспортом gRPC.
Neuropipe должен использовать ту же модель:

1. запускать один управляемый долгоживущий sidecar на доверенный бандл;
2. выполнять фиксированный go-plugin handshake и разрешать только gRPC;
3. вызывать Describe и сверять runtime id и версию API с манифестом;
4. регистрировать проверенные узлы в общей Blueprint-библиотеке;
5. вызывать ValidateConfig и отменяемый ExecuteAction;
6. предоставлять ToolDefinition и ExecuteTool для агентных инструментов;
7. поддерживать двунаправленный TriggerRuntime со снимками подписок;
8. останавливать sidecar при перезагрузке, выключении, ошибке и завершении
   приложения.

Этот транспорт и публичный SDK Neuropipe ещё не существуют. Раздел описывает
направление совместимости, а не доступный API. Будущий рантайм должен переносить
через RPC Blueprint-пины, границы кэша, capabilities, approvals, trust,
отмену, бюджеты, редактирование данных и метрики.

## Документация плагина

Страница плагина содержит id, title, categoryPath и относительный Markdown-путь;
summary и nodeTypes необязательны. Видимый идентификатор:
plugin:<plugin-id>:<document-id>.

Путь должен быть относительным, оканчиваться на .md, оставаться внутри бандла,
указывать на файл не больше 1 MiB, а id должен быть уникальным в бандле.
Ошибка документации не выключает исправный плагин; настройки покажут отдельную
диагностику. Markdown обрабатывается общим безопасным renderer.

## Состояние и обновления

После каждого изменения нажмите **Повторно обнаружить плагины**. Это не выдаёт
доверие и в текущей версии не запускает sidecar. Проверяйте происхождение и
исходный код каждого локально установленного плагина.

- **Healthy**: id, name, v1 и sidecar-файл прошли проверку.
- **Invalid manifest**: исправьте JSON, обязательное поле или версию API.
- **Sidecar unavailable**: соберите файл или исправьте его путь.
- **Диагностика документации**: исправьте метаданные, путь или размер.

Сохраняйте идентификаторы стабильными, используйте семантические версии и
перейдите к [первому плагину](docs:extensions/first-plugin).
