# Инструментальные функции LLM

Инструментальная функция LLM — это опубликованная переиспользуемая Blueprint-функция, которую **Агент** или **Кодовый агент** может вызвать через пин **Инструменты**. Это не узел выполнения: единственный выход Tool лишь объявляет инструмент доступным модели. Хост проверяет вызов, выполняет функцию и возвращает модели типизированный результат.

## Сначала создайте контракт

1. В разделе **Функции** выберите **Новая функция → Инструмент LLM**.
2. Опишите, *когда* модель должна использовать инструмент. Например: «Получить текущий прогноз для города. Использовать только для вопросов о погоде.»
3. Добавьте публичные входы и выходы. Для каждого пина нужна **подсказка для модели**: смысл, ограничения и пример.
4. Выберите конкретные типы, отметьте обязательными только нужные входы и публикуйте после создания достижимого пути **Function Entry → Function Return**.

Для публикации нужны описание функции, хотя бы один описанный выход, подсказки для всех пинов, конкретные типы и уникальные имена аргументов. У инструмента может не быть входов, но он обязан вернуть описанный результат.

## Пример: запрос погоды

Создайте инструмент **Получить прогноз города**:

| Часть | Контракт |
| --- | --- |
| Описание | «Получить текущий прогноз для города. Использовать для вопросов о погоде.» |
| Вход `city` | Текст, обязательный. Подсказка: «Город и страна, например `Yekaterinburg, RU`.» |
| Выход `forecast` | Текст. Подсказка: «Краткий прогноз с состоянием и температурой.» |

Внутри функции:

```text
Function Entry ──exec──> HTTP Request ──exec──> Function Return
      city ──data──> сопоставление HTTP ──data──> forecast
```

Опубликуйте функцию и подключите её выход **Tool** к входу **Инструменты** Агента. К одному пину можно подключить несколько независимых инструментов.

Пример инструкции Агенту:

> Ответь на вопрос о погоде. Если нужен текущий прогноз, вызови подключённый инструмент с городом и страной. Не выдумывай прогноз.

## Типы на границе модели

Аргументы инструмента передаются как JSON, затем Neuropipe декодирует их в точный `TypeSpec`: текст и boolean остаются JSON-значениями, целое число не должно иметь дробной части, байты передаются строкой Base64 и декодируются в `[]byte`, списки проверяют каждый элемент, map используют текстовые ключи, анонимные records проверяют объявленные поля.

`any`, именованные Go-record и map с нетекстовыми ключами нельзя использовать в публичном контракте инструмента. Не выполняются неявные преобразования текста в число, целого в float или байтов в текст — используйте явный узел преобразования в графе.

## Вызовы и безопасность

Агент ограничен настроенным количеством ходов. Неизвестный аргумент, отсутствие обязательного значения, неверный тип, ошибочная Base64-строка или неизвестное поле record возвращаются модели как безопасная ошибка контракта, чтобы она могла исправить вызов. Внутренние ошибки не раскрывают локальные пути, секреты или полезные данные.

Функции по-прежнему нужны только возможности её внутренних узлов; обычные локальные проверки доверия и разрешений остаются обязательными. Не помещайте секреты в описание, подсказки, инструкции Агенту или результаты инструмента.
